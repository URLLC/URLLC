# Dazi MVP 发布检查清单

## 上线前配置

- 在 Vercel（或其他托管平台）配置 `NEXT_PUBLIC_SUPABASE_URL` 与 `NEXT_PUBLIC_SUPABASE_ANON_KEY`。
- 仅当管理端批量建号功能确有需要时，配置 `SUPABASE_SERVICE_ROLE_KEY`；它绝不能以 `NEXT_PUBLIC_` 前缀暴露。
- 在 Supabase Auth 的 URL Configuration 中加入正式域名与 `https://<domain>/auth/callback`。
- 按顺序执行 `docs/07` 至 `docs/10` 的 SQL，并确认每次显示 `Success`。

## 手工验收（15 分钟）

1. 新邮箱注册并完成验证，确认会自动生成 `users` 资料行。
2. 编辑昵称、学校、简介和标签，刷新后确认资料仍存在。
3. 发布一场未来活动，确认发起人自动成为成员，首页、地图与详情人数一致。
4. 用第二个账号加入活动；重复报名应被拒绝，满员时不能再加入。
5. 在同一活动的成员主页发送联系申请；接收方能在“消息”页接受或拒绝。
6. 发送评论、复制活动链接、取消一场未开始的自己发起的活动。
7. 在手机宽度下检查底部导航、发布按钮和详情页底部操作条。

## 演示数据建议

- 准备 2 个已验证账号、3 场未来活动和 1 场已满员活动。
- 每场活动写清时间、集合点、人数和费用/准备事项，避免空泛描述。
- 不使用真实手机号、住址或私人敏感信息。

## 已知 MVP 边界

- 联系申请是建立沟通许可，不是即时聊天；即时消息可作为下一阶段功能。
- 地图使用 OpenStreetMap 瓦片，正式高流量场景应评估符合其使用政策的地图服务。
- 取消活动目前为关闭状态，不会删除历史记录。
